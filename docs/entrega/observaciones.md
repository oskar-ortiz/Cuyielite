# Formato de observaciones — prueba con Luis/SENA

Una observación por hallazgo. No prellenar resultados, responsables ni estados.

| Campo | Contenido |
|---|---|
| Identificador | `OBS-___` |
| Rol / plataforma / versión | Participante, Windows o Android, SHA-256 de la candidata |
| Pasos de reproducción | 1. … 2. … 3. … |
| Resultado esperado | Según el caso AT-__ del plan de aceptación |
| Resultado observado | Texto literal de pantalla o behavior; sin interpretaciones |
| Impacto | Usabilidad / funcionamiento técnico / validación de dominio |
| Evidencia | Ruta de captura o log; sin credenciales ni datos reales |
| Responsable | Nombre del responsable del frente |
| Acción | Corrección, aclaración, elevación a decisión de dominio o sin acción |
| Estado | Abierta / en revisión / cerrada / no reproducible |

Reglas: una observación no es una aprobación; un hallazgo de dominio se documenta y se eleva, no se corrige cambiando reglas zootécnicas ni el frente RAG de Diery. No adjuntar datos identificables, reportes privados ni credenciales a este paquete.
